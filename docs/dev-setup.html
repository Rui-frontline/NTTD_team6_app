アプリを自分のPCで動かす

前回の手順書で VS Code・Git・GitHubアカウントまで準備できました。 ここからは実際にアプリを自分のパソコンで起動するところまでやります。 当日みんなで一緒に進めるので、途中で分からなくなったらその場で手を挙げてください。

所要時間
25〜40分
前提
手順書その1が完了
ゴール
ブラウザでアプリが動く
進め方
全員でそろって

この手順書の流れ

  1. Node.js を入れる— アプリを動かす土台
  2. プロジェクトをコピーする— clone
  3. 必要な部品を取り込む— npm install
  4. アプリを起動する— ここでやっと画面が出ます
  5. 自分のブランチに移る— コードを書く人だけ
  6. うまくいかないとき
  7. 用語集
今日やることの全体像

アプリを動かすには、4つのものが自分のパソコンに必要です。

  • Node.js … JavaScript をパソコン上で動かすための土台。これがないと何も始まりません
  • プロジェクトのコード … GitHub にあるものを自分のPCにコピーしてきます
  • 部品（パッケージ） … 他の人が作った便利な部品。コマンド1つで自動でそろいます
  • 開発サーバー … 自分のPCの中だけで動く、確認用のサーバー

上から順にやれば必ず動きます。飛ばさないでください。

01

Node.js を入れる

必須 約10分

Node.js（ノードジェイエス）は、JavaScript というプログラミング言語をパソコン上で動かすための土台です。今回のアプリはこれがないと1行も動きません。

インストール手順Windows

  1. nodejs.org を開きます。

  2. 「LTS」と書かれた緑のボタンを押します。

    LTS は「長期サポート版」という意味で、安定していて安全な版です。隣に新しい番号のボタンがありますが、そちらは選ばないでください。

  3. ダウンロードされた node-v〇〇-x64.msi をダブルクリックします。

  4. 「Next」を押し続けます。途中で設定を変える必要はありません。使用許諾に同意するチェックだけ入れてください。

  5. 「Tools for Native Modules」という画面が出たら、チェックは入れずに Next で構いません。

  6. 「Install」→「Finish」で完了です。

インストール手順Mac

  1. nodejs.org を開きます。

  2. 「LTS」と書かれた緑のボタンを押します。

    LTS は「長期サポート版」という意味で、安定していて安全な版です。隣に新しい番号のボタンがありますが、そちらは選ばないでください。

  3. ダウンロードされた node-v〇〇.pkg をダブルクリックします。

  4. 「続ける」を押し続けます。設定を変える必要はありません。

  5. 最後にMacのパスワードを求められるので入力して 「ソフトウェアをインストール」。

ここが一番の落とし穴

インストールが終わったら、VS Code とターミナルを一度すべて閉じて開き直してください。

再起動しないと、パソコンが Node.js の存在に気づきません。「入れたのに認識されない」の9割はこれが原因です。

入ったか確認する

VS Code を開き、上のメニューから 「ターミナル」→「新しいターミナル」 を選びます。画面の下半分に黒い領域が出てきます。

そこに次を貼り付けて Enter を押してください。

node -v

続けてもう1つ。

npm -v

こんな感じで数字が2つとも表示されれば成功です。番号は違っていて構いません。

v24.17.0
11.13.0
Windows：ここで止まる人が多いです

node -v は通ったのに npm -v だけこう出た場合：

npm : このシステムではスクリプトの実行が無効になっているため、
ファイル C:\Program Files\nodejs\npm.ps1 を読み込むことができません。

故障ではありません。Windows の初期設定です。ターミナルを切り替えるだけで直ります。

  1. ターミナル画面の右上にある「＋」の横の下向き矢印（∨）をクリック。

  2. リストから 「Command Prompt」 を選ぶ。

  3. 新しく開いたターミナルで、もう一度 npm -v を実行。

さらに、これを既定にしておいてください。やらないと次に開いたときに同じことが起きます。

  1. Ctrl + Shift + P を押す。

  2. Terminal: Select Default Profile と入力して選ぶ。

  3. Command Prompt を選ぶ。

以降のコマンドはすべて Command Prompt で問題なく動きます。システムの設定を変える必要はありません。

これはエラーではありません

バージョンの下にこういう表示が出ることがあります。

npm notice New major version of npm available!
npm notice To update run: npm install -g npm@...

「新しい版がありますよ」というお知らせです。1行目にバージョンが出ていれば成功なので、無視して次に進んでください。更新する必要もありません。

バージョンの条件

今回のアプリは Node.js 20.9 以上が必要です。node -v の表示が v20 より小さい場合は、上の手順でもう一度 LTS 版を入れ直してください。

ここまでできたら OK
  • node -v でバージョンが出る（v20 以上）
  • npm -v でバージョンが出る
02

プロジェクトを自分のPCにコピーする

必須 約5分

GitHub にあるコードを、自分のパソコンに丸ごとコピーしてきます。この作業を クローン（clone）と呼びます。

チームのリポジトリURL

このURLを使います。右の COPY ボタンでコピーしてください。GitHub で探す必要はありません。

https://github.com/Rui-frontline/NTTD_team6_app.git

コピーできたら、下のどちらかの方法に進んでください。不安な人は方法Aがおすすめです。

方法A：VS Code の画面だけで行う（おすすめ）

ターミナルを使いません。不安な人はこちらでどうぞ。

  1. VS Code を開きます。何もフォルダを開いていない状態で構いません。

  2. 左のバーの枝アイコン（ソース管理）をクリックします。

  3. 「リポジトリのクローン」ボタンを押します。

  4. 画面上部に入力欄が出るので、上のURLを貼り付けて Enter。

  5. 保存先のフォルダを選ぶ画面が出ます。「ドキュメント」など分かりやすい場所を選んでください。

    選んだフォルダの中にプロジェクト用のフォルダが自動で作られます。

  6. GitHubへのサインインを求められたら「許可」を押し、ブラウザで承認してください。private リポジトリなので、この認証が必要です。

  7. 終わると「開きますか？」と聞かれるので 「開く」 を押します。

方法B：ターミナルで行う

まず、保存したい場所へ移動します。「ドキュメント」に置く場合はこちら。

cd ~/Documents

エラーが出る場合（OneDrive を使っていると場所が違います）は、この行は飛ばして構いません。今いる場所にそのままコピーされます。

そのまま貼り付けて実行できます。書き換える箇所はありません。

git clone https://github.com/Rui-frontline/NTTD_team6_app.git

できたフォルダの中に入ります。

cd NTTD_team6_app

最後に、VS Code でこのフォルダを開きます。

code .
ここまでできたら OK
  • NTTD_team6_app というフォルダができている
  • VS Code の左側に app components lib docs などのフォルダが見えている
03

必要な部品を取り込む

必須 約5分

アプリは、他の人が作った部品（パッケージ）をたくさん使って動いています。その部品は GitHub には入っていないので、自分で取り込む必要があります。

コマンド1つで全部自動でそろいます。

VS Code でターミナルを開く

上のメニューの 「ターミナル」→「新しいターミナル」。画面の下半分に出てきます。

プロジェクトのフォルダを開いた状態で開いてください。別の場所で実行すると失敗します。

npm install
実行中に知っておくこと
  • 2〜5分かかります。文字がたくさん流れますが、待っていれば終わります
  • 黄色い warning（警告）はすべて無視して構いません。赤い error だけ気にしてください
  • 終わると node_modules という巨大なフォルダができます。これが部品の置き場です。GitHubには送られない設定になっているので、気にしなくて大丈夫です

最後にこんな表示が出れば成功です。

added 358 packages, and audited 359 packages in 40s

found 0 vulnerabilities
ここまでできたら OK
  • added ○○ packages と表示された
  • 左のファイル一覧に node_modules ができている
04

アプリを起動する

必須 約2分

ここでやっと画面が出ます。

npm run dev

数秒待つと、こんな表示が出ます。

▲ Next.js 16.3.0
- Local: http://localhost:3000

✓ Ready in 1.8s

ブラウザで http://localhost:3000 を開いてください。ターミナルに出ている http://localhost:3000 を Ctrl を押しながらクリックしても開けます。

「社内マッチング」というログイン画面が出れば成功です。おつかれさまでした。

動かしている間の話
  • 起動している間、ターミナルは操作できません。これは正常です。別のコマンドを打ちたいときは、ターミナルを新しくもう1つ開いてください
  • 止めるときは、ターミナルをクリックしてから Ctrl + C。これは Windows も Mac も同じです
  • 起動したままコードを書き換えると、画面が自動で更新されます。いちいち止める必要はありません
  • localhost は「自分のパソコンの中」という意味です。他の人からは見えません
ここまでできたら OK
  • ブラウザに「社内マッチング」のログイン画面が出た
  • 誰かを選んでログインすると、上に「仕事／恋愛」の切替が出る
  • 切り替えると色が変わる
05

自分のブランチに移る

コードを書く人だけ 約2分

担当のブランチはすでに用意してあります。作るのではなく、移るだけです。

方法A：VS Code の画面だけ（おすすめ）

  1. VS Code の左下に main と出ています。そこをクリック。

  2. 上部にブランチの一覧が出るので、自分の担当を選ぶだけです。

  3. 左下の表示が変われば完了です。

方法B：ターミナル

最新のブランチ情報を取ってきます。

git fetch

自分のブランチに移ります（feat/discover の部分を自分の担当に置き換えてください）。

git switch feat/discover
守ってほしいこと

main では作業しないでください。必ず自分のブランチに移ってから編集を始めます。

迷ったら左下のブランチ名を見る癖をつけてください。main と出ていたら、まだ移れていません。

ダミーデータ担当の人へ

ここまでの作業、実は不要です。編集するファイルが1つだけなので、もっと簡単な方法があります。

GitHub でリポジトリを開き、ブランチを feat/dummy-data に切り替えて、キーボードで .（ピリオド）を1回押してください。

ブラウザの中に VS Code がそのまま開きます。インストールもクローンも要りません。編集して左の枝アイコンからコミットすれば、それで完了です。

うまくいかないとき

症状対処
「node は認識されていません」
「command not found: node」		 VS Code とターミナルを全部閉じて開き直してください。それでも直らなければ、Node.js のインストールが完了していません
Windows で
「このシステムではスクリプトの実行が無効になっている」		 PowerShell の制限です。ターミナル画面の右上にある「+」の横の下向き矢印から「Command Prompt」を選んで、新しいターミナルを開き直してください。そちらなら動きます
「Port 3000 is already in use」 すでにアプリが起動しています。前のターミナルで Ctrl + C を押して止めるか、表示された別のポート番号（3001など）でブラウザを開いてください
npm install が終わらない 5分程度は正常です。10分以上かかるならネットワークを確認。それでもダメなら Ctrl + C で止めて、もう一度 npm install
画面が真っ白／エラー表示 ターミナルに出ている赤い文字をそのままスクショして共有してください。自分で直そうとしなくて大丈夫です
GitHubのサインインが通らない ブラウザで GitHub にログインしているか確認してください。リポジトリへの招待を受諾していない可能性もあります
お願い

詰まったら5分以内に声をかけてください。一人で粘る時間がもったいないです。エラーの文字は要約せず、スクショでそのまま見せてください。

ネットで見つけたコマンドを、意味が分からないまま実行しないこと。パソコンの設定が壊れることがあります。

用語集

Node.js
JavaScript をパソコン上で動かすための土台。今回のアプリの動作に必須です。
npm
Node.js と一緒に入る、部品を取り寄せる道具。npm install で使います。
パッケージ
他の人が作った再利用できる部品。自分で全部作らずに済みます。
node_modules
取り寄せた部品の置き場。巨大ですが GitHub には送りません。消しても npm install で復活します。
クローン（clone）
GitHub のコードを自分のパソコンにコピーしてくること。
ローカル
「自分のパソコンの中」という意味。
localhost
自分のパソコンの中で動いているサーバーの住所。他の人からは見えません。
ポート
サーバーの入り口の番号。今回は 3000 番を使います。
開発サーバー
確認用に自分のPCで動かすサーバー。npm run dev で起動します。
